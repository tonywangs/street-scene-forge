# Fixture provenance and licenses

## Synthetic

`synthetic.osm` is **invented data**, centered near longitude/latitude zero. It is
not an extract from OpenStreetMap and must not be represented as a real place.
Regenerate it with `python3 scripts/make_synthetic.py`. The fixture intentionally
includes a hostile-looking name as inert text, invalid/self-intersecting and
unclosed footprints, a missing reference, a bridge, a boundary crossing, and an
unsupported relation. Expected export: 5 features, 6 omission diagnostics using
bbox `-0.0009 -0.0009 0.0009 0.0009`.

The synthetic XML and generated benchmark inputs are dedicated to the public
domain under [CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/).
The generator scripts have the repository's MIT code license.

The benchmark generator, `scripts/generate_workload.py`, produces a reproducible
1,000-building grid. It is synthetic too; its bbox is `-.006 -.006 .006 .006`.
It needs no acquisition and is regenerated during verification.

## Real OpenStreetMap snapshot

`berlin-six-ways.osm` is a deliberately small union of **six selected real OSM
ways and their referenced nodes**, around Berlin. It is not a complete area
extract, and absence of a feature says nothing about the real neighborhood.

- Acquired: 2026-10-10 UTC.
- Bytes: 15,365.
- SHA-256: `480ddb9155d0fb644a37748cb9df79be065f49796ba89f2b9081b037f955e988`.
- Source way IDs: 23853131, 23853133, 234463917, 51912365, 113595955, 16873017.
- Expected export: 6 features, plus 4 tagged-node omission diagnostics.
- Exact bbox, acquisition time, six URLs, response byte lengths/hashes, retained
  attributes, and transformations: [`berlin-six-ways.provenance.json`](berlin-six-ways.provenance.json).

The acquisition helper downloads each explicit `/api/0.6/way/{id}/full`, merges
repeated elements, and strips contributor account/changeset attributes. It keeps
IDs, versions, timestamps, coordinates, references, and tags. Geometry is unchanged.
An initial bounded area-request attempt exceeded a 2 MB acquisition cap and was
not used as this fixture; the explicit-way procedure is the reproducible method.

Optional **online acquisition** into a new directory:

```sh
python3 scripts/acquire_fixture.py --output /tmp/new-osm-snapshot
```

The remote map changes. This command acquires a **new snapshot**, not necessarily
the checked-in bytes. Use the committed extract/hash for exact experiment
reproduction. The offline CLI and verification do not run acquisition. Response
caps/timeouts are built into the helper; it never purchases data or uses credentials.

## Courtyard fixtures

`courtyard.osm` is CC0 synthetic data generated by
`tests.multipolygon_cases.demo()`. It contains a fragmented outer rectangle,
a fragmented courtyard, conflicting member heights (intentionally ignored), an
inert hostile relation name, and a separate unsupported route relation.

`multipolygons/` freezes four handcrafted OSM2World regression files at revision
`f6518b35117cf7864e9c6f68c3b303a006e27b8f`. Exact original XML bytes are preserved.
Their MIT license is included as `LICENSE.OSM2World`; these are upstream test
fixtures, not a sample of real-world map coverage. `provenance.json` records
immutable raw URLs, SHA-256 values, bounds, independently specified expectations
and the explicit adaptation used by tests. Since the originals describe road
areas, tests add `building=yes,height=7` to relations; the legacy outer-tag case
adds those tags only to the tagged outer way and must remain unsupported.

Closed and fragmented two-courtyard fixtures must export one three-ring building.
Touching inners must be rejected; legacy outer tags must not fill the courtyard.
Expected areas are frozen from independent GEOS polygonization/difference of
source member linework. Acquisition is not part of verification, and verification
fails if original bytes differ from the pinned hashes.

## Real Berlin neighborhood (playable demo)

`berlin-neighborhood.osm` is a bounded Overpass snapshot acquired at
2026-10-19T04:33:46Z. Bbox: west 13.403, south 52.519, east 13.4075,
north 52.522. The recursive query, response and transformed input hashes,
retrieval time, license, and transformation are in
[`berlin-neighborhood.provenance.json`](berlin-neighborhood.provenance.json).
The 749,978-byte XML retains IDs, geometry, tags, versions, and source timestamps;
only contributor account/changeset attributes and XML formatting were changed.
Recursive dependencies may extend beyond the requested bbox. Conversion omits
whole unsupported/out-of-bounds features instead of clipping them.

Map data © [OpenStreetMap contributors](https://www.openstreetmap.org/copyright),
[ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/). The code's MIT license
does not relicense this extract, its generated geometry, or the map depicted in
screenshots. The portable demo redistributes `source.osm` and its acquisition
record alongside the generated scene; keep these and the attribution together.
Regenerate with `python3 scripts/demo.py --export NEW_DIRECTORY`. A fresh online
acquisition uses `python3 scripts/acquire_neighborhood.py --output NEW_DIRECTORY`;
it is a new snapshot, not an exact replay of changing OSM data.
